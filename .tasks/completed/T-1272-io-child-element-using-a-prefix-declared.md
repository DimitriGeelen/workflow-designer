# T-1272: io child element using a prefix declared on the source root loses that declaration on save: export not well-formed (T-1243 regression; blocks 0.25.0)

## Context

Found by ring20 cloud job B (`docs/reports/T-2466-cloud-job-B-foreign-content.md`, row "x:schema in aef:input"): an
io child that uses a prefix the SOURCE root declares (`<x:schema>` with `xmlns:x` on `<bpmn:definitions>`) is kept by
`ioChildXml` (T-1243), which strips every declaration the source root makes; our export root declares only bpmn,
bpmndi, dc, di and aef, so `x:` is undeclared and the export is not well-formed. The same function writes the T-1249
verbatim io block and the process-level `aef:meta`, so all three paths had the hole. Regression in 0.25.0's T-1243;
release blocker for T-1255.

## RCA

**Symptom:** ring20's cloud job B: an `<x:schema>` inside `aef:input`, with `xmlns:x` on the source root, was exported
without any `xmlns:x`, so the export was not well-formed (AEF or any XML reader would refuse it).
**Root cause:** `ioChildXml` (T-1243) dropped every declaration the SOURCE root made, on the assumption that our export
root makes the same ones; it makes only five.
**Why structurally allowed:** `_t1243`'s foreign child declared its namespace on itself, never on the root, and no leg
parsed the export as XML; the root-declared case (how Camunda, Zeebe and most producers write) was untested.
**Prevention:** `_t1243` leg 6 (bridge leg): root-declared prefixes and default namespace, one-line and designer layout,
unedited and edited, export checked well-formed by DOMParser and expat.

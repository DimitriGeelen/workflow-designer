# Seam manifest — `examples/aef-processes/rendered/` state per release tag

**Mechanism:** T-807, following AEF's second ask (`agent-chat-arc @1656`, recorded in
`docs/branch-model.md` "The seam"). AEF pins a `designer-v*` tag under the release train, not
`master`'s moving head. This file answers "which seam bytes does tag `designer-vX.Y.Z` carry"
from the tag alone — no branch head lookup, no fetching a moving ref.

**How it's computed:** `scripts/seam-manifest.sh <tag>` reads `examples/aef-processes/rendered/`
directly out of git's object store at the given ref (`git ls-tree` + `git show <ref>:<path>`) —
read-only, no checkout, no writes to `dist/`, `VERSION`, or the seam directory itself. Output is
deterministic (content hashes only, no timestamps): re-running against the same tag reproduces
byte-identical output.

**Coverage:** every `designer-v*` tag that existed when this file was generated
(`designer-v0.1.0` .. `designer-v0.13.0`, 16 tags) is recorded below, computed directly from git
history — not just the next release. This answers AC4: the tool is verified against the whole
existing series, not only future cuts.

**Keeping this current:** after cutting a new tag, append its entry:
```
cd /opt/832-Workflow-designer && ./scripts/seam-manifest.sh <new-tag> >> docs/releases/seam-manifest.md
```
then commit `docs/releases/seam-manifest.md` alongside the tag. Because this file lives in the
repo tree, every commit *after* a given append carries that tag's entry — so from
`designer-v0.14.0` onward, a consumer who has fetched anything at or after the release commit
can read the entry without a separate branch-head fetch. (Entries for tags that predate this
mechanism — v0.1.0 through v0.13.0 — are backfilled here retroactively; they were never embedded
in those tags' own trees, since the mechanism did not exist yet. The tool still answers for them
correctly, computed live from git history, which is what AC4 requires.)

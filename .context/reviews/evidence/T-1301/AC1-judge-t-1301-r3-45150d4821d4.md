# T-1301 Human AC#1: independent review (judge-t-1301-r3-45150d4821d4, revision 005eb2fc)

## What I did
- Viewed the T-1301 evidence (docs/reports/T-1301-evidence/): stylea-edit 1024 panel + panel-end, stylea-edit 1024 full window, stylea-edit 1920 panel, hint-edit 1024 panel, v1-edit 1440 panel, stylea-step 1024 panel, v11-step 1440 panel.
- Compared them with T-1304 (0.27.0) by pixel (PIL ImageChops) for every shared filename, and by eye for stylea-step-1024-panel and v11-step-1440-panel.

## Findings
- **Toggle:** "▸ edit attributes" / "▾ close editor" shows under each io row at every width checked. The open state reads as an editor: there's an accent bar, the label column sits beside the input column, and the empty fields have visible input boxes.
- **Fields:** ref, fieldRef, typeRef, schemaRef, conceptRef, sourceSystem/targetSystem and dataType are all visible with labels. Values are shown whole, with no clipping: nid:attr-opportunity-id, nid:attr-account-company, id, string, zz:Thing.
- **Selects:** role, operation and cardinality each show a value and an arrow. The "use a ref from this map" picker under ref is unclipped.
- **Prefix hint:** the undeclared-prefix hint ('prefix "zz" is not declared in this map') sits directly under typeRef inside the editor block (hint-edit-1024-panel).
- **Row ownership:** each editor block is bracketed by the accent bar and sits under its own io row. When two editors are open (one input, one output) they stay distinct. At 1024 the second editor needs a scroll, and panel-end shows it whole.
- **Untouched states:** empty-step and workflow panels are byte-identical to T-1304 at 1024/1440/1920. The full-window diffs are limited to a small toolbar region (the version/status chip). In stylea-step and v11-step, the only visible change from 0.27.0 is an added "▸ edit attributes" line under each io. v1-step showed pixel differences in the same pattern, but I did not view those shots.

## Notes (outside this AC's scope; not counted against it)
- The io *name* inputs (e.g. "sfdc:Opportunity.Id", "tacton:Account.companyNa…") are truncated by the fixed panel width. This is identical in T-1304 (0.27.0), so it is not caused by T-1301. T-1305 owns the panel layout.
- None of the shots holds a value long enough to wrap, so I saw the wrapping behaviour only indirectly. No value in any shot is clipped. The task says harness leg g asserts that no field clips.

## Edge case I checked
A node whose type a user changed would get no `aef:eventDef` (empty binding) and could be retyped back to its native
kind on re-import. I found no node-type change in the designer: the only `.type =` assignment on a model object is a
field-list item (src:8076). So this cannot happen today.

## Ruling on the open question
**Plain catch/throw rendering, not a new generic type.** This is the same ruling as all three earlier rounds, and it
is recorded in Decisions. The node keeps its original tag (catch/throw, boundary, start, end) and its verbatim
definition. It has no link semantics and shows its kind read-only. No palette type is added: the designer cannot bind
signal, escalation, conditional, compensate, cancel or terminate, and T-190 IW-1 keeps designer-authored maps off native
definitions.

## Advisory (not blocking)
Once a user sets a binding on a third-party timer, message or error event, `aef:eventDef` carries the designer's value
and the verbatim native definition still carries the source's value (for example the original timeDuration). The two
can disagree. Other BPMN tools will read the native one. Rewriting native definitions is outside this task by its own
"Not proposed" clause. It is worth a follow-up note, or a line in the AC#4 diff review.

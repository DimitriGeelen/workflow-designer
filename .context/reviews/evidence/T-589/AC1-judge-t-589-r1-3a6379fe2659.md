# T-589 AC1 — Links field: raw textarea + rendered anchors (reviewer evidence)

Revision: 1e670215188c9fb38e2868e3eede7df66856d47a

## What I checked
1. Code: `src/aef-workflow-designer.html` `linkList` branch (~L6618): `field(..., {textarea:true})`
   then, for each trimmed non-empty line, `linkRow()` if `isNavigableUrl()` else `plainRow()`.
   `field()` re-renders the panel on blur (L6869), so anchors appear on "click elsewhere".
2. Headless Chromium (Playwright) against the review's own serve recipe (gallery-serve.py on a
   random port, src copy as designer.html). Selected a serviceTask, typed into **Links**:
   `https://example.com/code`, `/fabric/component/bpmn-cli`, `javascript:alert(1)`, then blurred.

## Found
- Textarea value after commit is exactly the raw typed text (all three lines preserved).
- Anchors rendered underneath: `https://example.com/code` and `/fabric/component/bpmn-cli`,
  both `target=_blank rel="noopener noreferrer"`.
- `javascript:alert(1)` rendered as muted non-clickable text (whitelist works; no XSS link).
- Screenshot: AC1-links-panel-judge-t-589-r1-3a6379fe2659.png — textarea on top, anchors below, both present at once.

## Judgement
Behaviour matches Expected exactly. The duplication is a deliberate split between the editing
surface (textarea) and the navigation surface (anchors); the muted row for non-URLs shows *why*
a line isn't clickable, which an anchors-only-when-unfocused shape would hide during editing.
This is a reversible UI-shape choice — not a Tier-0, irreversible or direction call — so it does
not need the human. Acceptable as is.

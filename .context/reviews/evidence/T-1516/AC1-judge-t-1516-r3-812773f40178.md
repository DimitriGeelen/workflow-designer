## Findings

1. **Rule 15 contradicts the Never section (amber).** Rule 15 says a picture may be linked "by a relative path (or the
   hosting site's raw link). That is not an outside service." The Never section says publishing maps or pictures to an
   outside service needs the owner's project switch (AEF: `PUBLISH_TO_ANTHROPIC`, default deny). A raw link on a public
   repository publishes the picture. For a private repository it does not. The skill states this as a flat fact and
   does not mention the switch. An agent could publish a picture by following rule 15. Needed: either remove the
   raw-link option, or state that a public repo or raw link is publication, governed by the Never rule and the owner's
   switch. AEF proposed the raw-link option in its review, so the author should confirm with AEF before editing.
2. **Rule 17 "then `renderAll()`" is redundant (nit, not wrong).** `adoptImportedXml` already calls `renderAll()` (l.~14181,
   inside the function body after `saveActiveToLibrary()`). Harmless; optional to drop the extra call.
3. **Not evaluated, not counted against the criterion:** rule 7 ("name every start and end event" as an unnamed one is
   shown by its id), rule 4's "a lane added after the phases makes the pool taller" and rule 12's round-trip defect
   examples are sourced to 832 tasks (T-1218, T-1504, T-1513, PL-030, PL-218) that I did not open. They are not
   contradicted by the source I read.

## Finding 1 — factual error about the designer (rule 17)
Rule 17 says: "Wait until `_appReady === true` before doing anything", then open the map with adoptImportedXml and renderAll.
The designer's own source says otherwise for a map opened by `?load=`. src/aef-workflow-designer.html l.14879–14882:
"_appReady flips at the end of Init, before this async fetch lands, so anything that drives the editor (the CDP probes)
must wait for this, not for _appReady plus a sleep." The settled signal is `window._deepLinkSettled` (null until the deep
link is adopted, 'none' | 'adopted' | 'suppressed' | 'failed' after). Rule 5 tells the agent to use exactly that `?load=` URL, so
rule 17 as written reads the editor before the deep-linked map is in. This is the race the 832 log records (T-1504 B5/B6).
The prior run's check only confirmed that `_appReady` exists; it did not test whether it is sufficient for `?load=`.
Also minor: adoptImportedXml already calls renderAll() (l.14181), so "then renderAll()" is redundant (harmless).
